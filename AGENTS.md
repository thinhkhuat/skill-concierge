# AGENTS.md

Agent-contributor instructions for **skill-concierge** — a skill-governance layer for
Claude Code, Codex, Command Code, Oh My Pi (OMP), ZCode, DeepSeek Harness (DSH), and Cline: semantic retrieval (*which* skill) +
use-enforcement (*whether* a skill is used at all) + a compounding invocation ledger
(*what* actually got used).

This file follows the open [AGENTS.md](https://agents.md/) convention and is the **canonical**
agent-instruction surface; platform adapters (e.g. [`CLAUDE.md`](CLAUDE.md)) point here. For
the full product overview see [`README.md`](README.md); for the *why* behind each decision see
[`docs/adr/`](docs/adr/README.md).

## Repository layout

The full tree is in the README's *Architecture* section. The parts you will touch most:

- `skills/{skill-search,setup,doctor,skill-usage-audit,keep-on,blocklist,flywheel,catalogs,consult}/SKILL.md` — the plugin skills (router + maintenance + usage-audit + keep-on allowlist manager + blocklist disable-tier manager ADR-0046 + flywheel utterance coverage/generation ADR-0027 + external catalog-roots manager ADR-0031 + consult deliberation layer ADR-0049)
- `scripts/` — `doctor.py` (health check), `analyze.py` (ledger; `--since`/`--until` window it by event time for before/after compares — don't split the ledger by hand), `apply-overrides.py` (keep-on writer; `--check`/`--if-changed` drift modes), `keep-on.py` (view/add/remove the always-on allowlist), `blocklist.py` (view/add/remove the disable list, ADR-0046), `catalogs.py` (external catalog roots: list/add/remove/promote, ADR-0031), `llm_capsules.py` (capsule-dossier generator, ADR-0049), `consult_log.py` (consult verdict ledger rows, ADR-0049), `embed_server.py` (warm embed sidecar), `engine_env.py` (the single `ENGINE_ENV_KEYS` list every reindex path forwards from `.mcp.json`, ADR-0058 — see *Runtime flags*)
- `hooks/` — the in-generation governance layer: `enforcer.py` (per-turn SKILL-FIRST gate: embed→retrieve→floors/intent→ranked mandate, plus the AUTHORIZED-SKIP tier — four legs: getaway + intent (ADR-0015), self-referential (ADR-0019), harness-message (ADR-0054, pre-I/O)), `skill_guard.py` (PreToolUse(Skill) deny on the blocklist — the disable tier's deterministic layer, ADR-0046), `skill_exclusions.py` (PostToolUse(Skill|get_skill) — echoes a just-loaded skill's own "not for" lines back deterministically, forcing an open re-rule instead of a silent switch; natively on Claude Code + ZCode, reached on OMP, Command Code, Cline and DSH through their adapters, which forward it the same load payload as `ledger.py`; quotes the copy the agent actually read via `tool_response` first, falling back to the index path then filesystem roots; ADR-0058, ADR-0059), `ledger.py` (invocation capture), `doctrine.py` (SessionStart standing-order injection), `auto_reindex.py` + `auto_overrides.py` + `auto_flywheel.py` (SessionStart self-heal: index + settings-override drift + utterance generation for new skills, ADR-0027 — fail-open, throttled, detached), `doctrine/skill-first.md` (the standing order + library doctrine — burden of proof on SKIP; a lawful skip has exactly two sources; real-or-ambiguous work escalates to a term-rich `search_skills` re-query, ADR-0056; the off-list route + the re-rule duty, ADR-0058)
- `vendor/skill-search/` — vendored MCP engine (MIT · sowhan/skill-search) — **do not diverge silently**; the body-derived trigger points (`_extract_body_triggers`/`_trigger_phrases`, ADR-0016) are a direct engine-code patch, logged in [`VENDORED.md`](vendor/skill-search/VENDORED.md) — re-apply it if the engine is ever re-vendored from upstream
- `.claude-plugin/{plugin,marketplace}.json` — plugin manifests
- `adapters/` — per-harness integration modules: `commandcode/` (mod adapter `skill-concierge.mod.ts` + install.sh + mcp.json, ADR-0038), `omp/` (extension module `skill-concierge.ext.ts` loaded via root `package.json` `omp.extensions`, install.sh, mcp.json, ADR-0039), `zcode/` (verifier/repair install.sh + manual-fallback mcp.json — ZCode needs NO adapter vehicle, it natively reads `.claude-plugin/` manifests, fires the plugin hooks, and auto-connects the plugin `.mcp.json`; ADR-0042), and `dsh/` (Cordis-plugin enforcement vehicle `skill-concierge.dsh.ts` riding `agent/pre-step`, installer writing the `skill-search` MCP row, the unlazy stop-hook and the enforcement plugin into each profile's `cordis.patch.yml` as `- insert:` patches (a bare `- id:` only overrides an existing entry — ADR-0059), reference mcp.json, ADR-0050 — DSH is a Cordis composition harness, not a Claude-format plugin consumer), and `cline/` (native file-hook bridge `skill-concierge.cline-hook.cjs` + shim templates + install.sh + mcp.json, ADR-0051 — Cline maps hook FILE NAMES to events and co-fires same-event files with merged contexts, so the adapter installs separate self-owned shims and never touches the operator's bridges). The OMP adapter never writes `~/.omp/agent/mcp.json` — OMP expands the plugin `.mcp.json`'s `${CLAUDE_PLUGIN_ROOT}` natively; the ZCode fallback likewise stays unwritten while the plugin layer is healthy.
- `package.json` — root manifest carrying the OMP extension hook: `{"omp": {"extensions": ["./adapters/omp/skill-concierge.ext.ts"]}}`.
- `.codex-plugin/plugin.json` + `.codex/hooks.json` — Codex adapter: manifest (no hooks field — auto-discovered) + repo-dev openwiki commit gate (ADR-0033)
- `config/keep-on.json` — the shipped SEED for the curated always-on allowlist (runtime copy seeded once into `~/.claude/skill-concierge/keep-on.json`, the canonical durable home; ADR-0025)

## Setup & verification

```bash
./setup.sh                  # idempotent: venv + Qdrant + reindex + apply-overrides
python3 scripts/doctor.py   # read-only health check (add --fix for safe repairs)
```

Run `doctor.py` (or the `skill-concierge:doctor` skill) before **and** after any change that
touches the engine, MCP wiring, or overrides. A green `status: OK` is the bar — claim "done"
only with that proof in hand.

**Doc/version drift guard:** `python3 scripts/driftcheck.py driftcheck.json` (exit 0 = synced). It
checks the version across the mirror set (`plugin.json` ↔ `marketplace.json` ↔ `.codex-plugin/plugin.json` ↔ latest `CHANGELOG.md` heading ↔ `README.md` ↔ `openwiki/quickstart.md`), that
every doc-referenced path exists, and that this file and `CLAUDE.md` name the same scratch dirs. Run it
after a version bump or after editing a fact shared between these docs.

## Conventions

- **Python:** 3.10–3.12, `snake_case`. `analyze.py` and `doctor.py` are **stdlib-only** — keep them dependency-free.
- **Shell:** `setup.sh` and the `bin/` launchers target POSIX `sh`/`bash`; keep them portable and idempotent.
- **Versioning:** bump `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `.codex-plugin/plugin.json`, AND root `package.json` together, plus a `CHANGELOG.md` entry. Never bump one alone — `driftcheck.json` mirrors the manifest/CHANGELOG/README/quickstart set, and `package.json` carries the OMP extension hook (`omp.extensions`), so its version must stay in lockstep even though driftcheck does not regex it.
- **ADRs are immutable.** Don't edit an accepted ADR — supersede it with a new one.
- **Vendored engine:** never patch `vendor/skill-search/` to diverge from upstream silently; record any customization in [`vendor/skill-search/VENDORED.md`](vendor/skill-search/VENDORED.md).
- **Tool state is not source.** `.ijfw/`, `ijfw/`, `.handoff/`, `logs/`, and `graphify-out/` are session/runtime scratch — gitignored, never committed. (`graphify-out/` is the knowledge-graph build: `graph.json`, `graph.html`, `GRAPH_REPORT.md`, and a per-file extraction cache — all rebuildable from source, so it is derived output, not source.)

## Runtime flags

Each is a one-var revert to the prior behavior (`ENFORCER_AUTHORIZED_SKIP`, `ENFORCER_CHAIN_HINT`, `ENFORCER_CROSS_HARNESS`, `ENFORCER_PROJECT_ISOLATION`, `ENFORCER_MINED_CHAINS`, `ENFORCER_MULTI_INTENT`, `ENFORCER_CHAIN_PROJECTION`, `ENFORCER_HARNESS_SKIP`, `ENFORCER_DETERMINISTIC`, `SKILL_BLOCKLIST`, `SKILL_CONSULT`, `SKILL_CONSULT_ROUTE`, `SKILL_ROW_ORIGIN`, and `SKILL_BODY_TRIGGERS` default ON; `SKILL_LLM_TRIGGERS` and `SKILL_SYNCED_ROOTS` default OFF):

- `ENFORCER_MULTI_INTENT` (`hooks/scripts/enforcer.py`) — code default ON (ADR-0041), but **switched OFF on this machine's Claude Code via `~/.claude/settings.json` env as a trial**: the human-prompt backtest of the v0.46.0 epoch showed no lift (84 multi-intent offers → 5 with ≥2 takes vs control 7/98) at ~245 chars on about half of all offers. Other harnesses keep the default; `ENFORCER_CHAIN_PROJECTION` stays ON until epoch-watch v0.47.0 W6 decides. [ADR-0055](docs/adr/0055-multi-intent-off-projection-pending.md).
- `ENFORCER_HARNESS_SKIP` (`hooks/scripts/enforcer.py`) — the harness-message lane: a prompt whose head is harness-generated (`<task-notification>`, `<system-reminder>`, cross-session/teammate messages, "[Request interrupted…", "This session is being continued…", an OMP `omp-msum` summarizer wrapper) is authorized to skip before the refusal guard, consult route, embed and every Qdrant call — ledger band `harness_skip`, fourth `SKILL-CHECK:` leg, no chain hint. `=0` routes such prompts like any other. [ADR-0054](docs/adr/0054-harness-message-lane-and-audit-fixes.md).
- `ENFORCER_DETERMINISTIC` (`hooks/scripts/enforcer.py`) — default ON since ADR-0054: `config/deterministic-routes.json` substrings pin the named skill to the top of the offer (score 1.0, retrieved twin dropped), computed BEFORE the embed step so a timeout cannot lose it. `=0` disables; an empty `routes` list is a no-op. Timeouts widened in the same ADR (`ENFORCER_EMBED_TIMEOUT` 0.5 s, `ENFORCER_QDRANT_TIMEOUT` 0.25 s — revert to 0.35 / 0.1 via the vars). Keep-off (ADR-0011) now lives in `~/.claude/skill-concierge/keep-off.json`, regenerated by `doctor --fix`; `SKILL_CONCIERGE_KEEPOFF` overrides the path.

- `SKILL_CODEX_ROOTS` (`vendor/skill-search/skill_search/skills_discovery.py`) — dual-harness discovery: index `~/.codex/skills` + `~/.codex/plugins/cache/**` alongside the Claude roots under distinct `codex-*` scopes (one shared collection; neither harness prunes the other's points). `=0` + a reindex restores Claude-only discovery byte-identically. The enforcer's chain-hint scope mirror honors the same flag. [ADR-0033](docs/adr/0033-dual-harness-codex-parity.md).

- `SKILL_OMP_ROOTS` (`vendor/skill-search/skill_search/skills_discovery.py`) — quadruple-harness discovery: index Oh My Pi's four skill roots alongside the Claude/Codex/Command Code ones under distinct `omp-*` scopes — `~/.omp/agent/skills` (`omp-personal`), `<cwd>/.omp/skills` (`omp-project:<abspath>`), `~/.omp/agent/managed-skills` (`omp-managed`), and `~/.omp/plugins/cache/plugins/**/skills/*/SKILL.md` (`omp-plugin`; the `node_modules` symlink farm is excluded structurally — every entry there resolves back into the same cache). One shared collection; neither harness prunes the other's points. `=0` + a reindex reverts to pre-OMP discovery byte-identically. Forwarded by `auto_reindex._mcp_env()`; the enforcer's `_running_harness()` resolves `omp` via `SKILL_CONCIERGE_HARNESS=omp/oh-my-pi` → `OMPCODE=1` → `.omp/` path marker, and `_invocable_plugin_ids()` under `omp` unions `~/.omp/plugins/installed_plugins.json`. [ADR-0039](docs/adr/0039-omp-quadruple-harness-parity.md).

- `SKILL_ZCODE_ROOTS` (`vendor/skill-search/skill_search/skills_discovery.py`) — quintuple-harness discovery: index ZCode's roots alongside the other four harnesses' under distinct `zcode-*` scopes — `~/.zcode/skills` (`zcode-personal`), `<cwd>/.zcode/skills` + `<cwd>/.agents/skills` (`zcode-project:<abspath>`), and ZCode's plugin cache (`zcode-plugin`), the latter **registry-enumerated** (`installed_plugins.json` installPaths + newest builtin version dirs, enablement-filtered) — never a wholesale cache glob. `~/.agents/skills` is deliberately NOT a root (it symlinks to `~/.claude/skills` on the reference machine; invocability is the enforcer's per-session twin check). One shared collection; `=0` + a reindex reverts byte-identically. Forwarded defensively by `auto_reindex._mcp_env()`; the enforcer's `_running_harness()` resolves `zcode` via `SKILL_CONCIERGE_HARNESS=zcode` → `ZCODE_PLUGIN_ROOT` (absolute) → `.zcode/` path marker, `_invocable_plugin_ids()` under `zcode` reads ZCode's own registries only, `_invocable_twin()` adds a filesystem twin (`~/.agents/skills`/`~/.zcode/skills`), and `_foreign_scopes()` treats `personal` as invocable iff `~/.agents/skills` resolves to `~/.claude/skills` (the shared-shelf symlink). [ADR-0042](docs/adr/0042-zcode-quintuple-harness-parity.md).

- `SKILL_DSH_ROOTS` (`vendor/skill-search/skill_search/skills_discovery.py`) — hexa-harness discovery: index DeepSeek Harness's roots alongside the other five harnesses' under distinct `dsh-*` scopes — `DSH_HOME/skills` (`dsh-personal`; DSH_HOME resolves to `~/.ohdsh` under Oh-DSH Desktop, else `~/.dsh`) and `<cwd>/.dsh/skills` (`dsh-project:<abspath>`). `~/.agents/skills` is deliberately NOT a root (ADR-0042 rule: invocability is the enforcer's per-session twin check). One shared collection; `=0` + a reindex reverts byte-identically. Forwarded by `auto_reindex._mcp_env()`; the enforcer's `_running_harness()` resolves `dsh` via `SKILL_CONCIERGE_HARNESS=dsh` → `DSH_SHELL=1` → `.dsh`/`.ohdsh` path marker, `_invocable_plugin_ids()` under `dsh` returns `None` (no plugin registry), and `_invocable_twin()` falls back to a filesystem twin (`DSH_HOME/skills/<name>/SKILL.md`). [ADR-0050](docs/adr/0050-dsh-hexa-harness-parity.md).

- `SKILL_CLINE_ROOTS` (`vendor/skill-search/skill_search/skills_discovery.py`) — hepta-harness discovery: index Cline's roots alongside the other six harnesses' under distinct `cline-*` scopes — `~/.cline/data/settings/skills` (`cline-personal`) and `<cwd>/.cline/skills` (`cline-project:<abspath>`). One shared collection; `=0` + a reindex reverts byte-identically. Forwarded by `auto_reindex._mcp_env()`; the enforcer's `_running_harness()` resolves `cline` via `SKILL_CONCIERGE_HARNESS=cline/cline-cli` (set by the adapter's file-hook bridge; Cline has no native env identity signal) → `.cline` path marker, `_invocable_plugin_ids()` returns `None` (Cline's AgentPlugin plugins contribute rules/commands/mcpServers/hooks/tools — never skills), and `_invocable_twin()` falls back to a filesystem twin (Cline's two skill roots). [ADR-0051](docs/adr/0051-cline-hepta-harness-parity.md).
- `SKILL_SYNCED_ROOTS` (`vendor/skill-search/skill_search/skills_discovery.py`) — **default OFF**, the one discovery-root flag that ships this way: indexes Claude account-synced skills at `~/.claude/skills/synced/<bucket>/<name>/SKILL.md` — exact depth, only names the bucket's `manifest.json` lists, real-path-guarded against a symlink escape — as `anthropic-skills:<name>`, scope `claude-synced`, carrying `creatorType`/`source` payload. `claude-synced` is foreign to every harness but Claude in `enforcer.py`'s `_foreign_scopes()`, and is excluded from the cross-harness foreign annex (`_retrieve_foreign`'s scope filter) and from `apply-overrides.py`'s `skillOverrides` discovery and `build_triggers.py`'s utterance/capsule corpus. The gate `_plugin_gate_ok(name, scope)` passes a row only when `scope == "claude-synced"` **and** `RUNNING_HARNESS == "claude"` — never on the `anthropic-skills:` name alone, which a plugin could also carry (a bare-name check is spoofable; scope is derived from the real filesystem path). Ships OFF until `doctor` shows every harness cache ≥`0.48.0`; `=1` + a reindex enables, forwarded through `scripts/engine_env.py` like every other engine-shaping flag. [ADR-0058](docs/adr/0058-off-list-rule-exclusion-echo-row-provenance-synced-default-off.md).

- `ENFORCER_EXTERNAL_ANNEX` (`hooks/scripts/enforcer.py`) — the external-catalog annex (ADR-0032, reinstated by ADR-0047 after the one-day ADR-0045 parity interlude was reverted as a regression): `_retrieve` always carries `must_not tier=external`, so the installed ranking and every gate (keepoff, blocklist, deterministic, getaway, actionability, tau, dominance, multi-intent) run on installed rows only — zero displacement is a hard invariant. Externals return via the SEPARATE `_retrieve_external` query: up to `ENFORCER_EXTERNAL_SLOTS` (4 dynamic / 2 fixed) rows clearing `_annex_floor(ENFORCER_EXTERNAL_FLOOR, top_installed)` render in a marked annex block (`[external:<alias>]` + the `get_skill` consumption instruction — they are not Skill-tool-invocable), blocklist-filtered (ADR-0046, new vs the 0.23.0 code). Tuned by ADR-0047 ("more helpful than the ADR-0032-era"): `ENFORCER_EXTERNAL_FLOOR` default 0.32 (was 0.40, ~1.8× `ITEM_FLOOR` instead of 2.2×). Chain sidecar/hints/ROUTE are installed-only (catalog scopes excluded); flywheel `--generate` defaults to installed-only with the auto-flywheel per-alias loop covering catalogs. Ledger `ext` records annex rows — EPOCH v0.41.0. Since ADR-0048 the annex is the builtin's COMPLEMENT: installed top ≥ `GETAWAY_FLOOR` → an external must beat it by `ENFORCER_ANNEX_BEAT` (0.04); below → plain-floor widening; demonstrated takes (`external-takes.json` digest from `auto_promote.py`, read live, fail-open) float first and render `used N×`; external query over-fetches `EXTERNAL_SLOTS×3`. `ENFORCER_ANNEX_COMPLEMENT=0` restores the ADR-0047 margin rule. `=0` (parity-era `ENFORCER_EXTERNAL_OFFER=0` honored as alias) restores the ADR-0031 search-only tier: no annex query, externals render nowhere. [ADR-0032](docs/adr/0032-external-catalogs-first-class-annex.md), [ADR-0047](docs/adr/0047-revert-tier-parity-restore-annex.md), [ADR-0048](docs/adr/0048-complement-annex.md).
- `ENFORCER_ANNEX_DYNAMIC` (`hooks/scripts/enforcer.py`) — competitive-margin sizing for the FOREIGN annex (ADR-0034) since ADR-0048: a foreign row earns its slot by scoring ≥ `max(FOREIGN_FLOOR, top_installed − ENFORCER_ANNEX_MARGIN)` (margin default 0.08, ADR-0047 tune of the measured 0.05; revert path `ENFORCER_ANNEX_MARGIN=0.05`), capped at 2. The EXTERNAL annex no longer uses the margin rule at all under the ADR-0048 complement default — beat gate or plain floor instead (see `ENFORCER_EXTERNAL_ANNEX`); the flag still governs the external `EXTERNAL_SLOTS` default (4 dynamic / 2 fixed) and the whole margin rule returns for externals behind `ENFORCER_ANNEX_COMPLEMENT=0`. Strong inventory → the foreign annex shrinks toward 0; thin inventory → widens to cap; deterministic hits silence it; no candidates → pool floor. The installed `TOP_K` is untouched. `=0` reverts byte-identically to fixed sizing. [ADR-0036](docs/adr/0036-dynamic-annex-sizing.md), [ADR-0048](docs/adr/0048-complement-annex.md).
- `ENFORCER_CROSS_HARNESS` (`hooks/scripts/enforcer.py`) — keeps the per-turn INSTALLED offer to skills the running harness can actually invoke. `_retrieve` over-fetches to `RETRIEVE_LIMIT` (`TOP_K*5`, headroom not a guarantee — a foreign-dominated domain can return a short menu), drops foreign-scope rows, trims back to `TOP_K`; `_retrieve_foreign` re-surfaces the top `ENFORCER_FOREIGN_SLOTS` (2) scoring ≥ `ENFORCER_FOREIGN_FLOOR` (0.40) from a SEPARATE query, each row marked with the harness whose roots actually hold it (`_scope_harness`, e.g. `[omp]`) rather than a hand-typed `[codex]`/`[claude]` label — ADR-0059 deletes the old per-harness `FOREIGN_HARNESS` constant, since nothing read it, ending that drift class — with the `get_skill` instruction; a dedicated query, so a foreign skill can never displace an installed slot. **A POST-filter, never a Qdrant `must_not scope`:** scope records where a skill's indexed copy LIVES, not invocability. Claude Code layers `enabledPlugins` across user → project → project-local settings while `_installed_plugin_roots()` reads only the user file, so a project-enabled plugin is dropped from discovery and its Codex twin wins the name — `_invocable_twin()` resolves installation (`installed_plugins.json`) plus the merged settings per session and keeps those rows in the offer — absent key = ENABLED (matching Claude Code), marketplace collisions resolve by union, and an unreadable manifest = "unknown" = **drop nothing** (the drop is conditioned on positive knowledge). Under DSH and Cline, which have no skill-plugin registry at all (`_invocable_plugin_ids()` returns `None` there by design), that same "unknown → drop nothing" rule used to switch the WHOLE foreign filter off; since ADR-0059 those two harnesses always run the foreign-scope check regardless, verdict by scope plus the shared `~/.agents/skills` shelf rule (`_agents_shares_personal_shelf()` — `personal` is foreign to them only when that root does not resolve to Claude's own `~/.claude/skills`) and a filesystem-twin rescue for the rest. That resolution stays in the hook, never in the machine-global index (ADR-0028 cwd-scoped-view hazard). Foreign scopes are DERIVED per running harness (`_foreign_scopes()`, one tuple per harness incl. `omp`/`zcode`/`dsh`/`cline`, completed to cover every discovery scope by ADR-0059 — Claude's own tuple had gaps too, e.g. `omp-managed`/`zcode-plugin` rows entering the Claude offer as if invocable); `personal` is not foreign to Codex, because discovery walks the Claude root first so a skill in both personal roots is tagged `personal` while Codex can still invoke it. Harness detection uses PRECEDENCE (`CLAUDE_PLUGIN_ROOT`, else the hook's own `__file__`) and never resolves a falsy candidate — `Path("").resolve()` is the cwd and would invert the filter. `search_skills` and chain hints keep ADR-0033's union. `=0` reverts to the pre-change request shape and output. [ADR-0034](docs/adr/0034-cross-harness-offer-isolation.md), completed by [ADR-0059](docs/adr/0059-harness-complete-offer-isolation-echo-everywhere.md).
- `ENFORCER_PROJECT_ISOLATION` (`hooks/scripts/enforcer.py`) — default ON (ADR-0059): drops a project-scoped offer row (`<family>:<skills dir>`) whose project root is neither the session's cwd nor an ancestor/descendant of it (the root is taken from the recorded scope path, then resolved only for the comparison, so a symlinked `.claude/skills` stays with its project; nested layouts are kept, never guessed at), UNLESS a same-named copy exists at the same relative path in the session dir or any parent (`_project_row_verdict` — the shared-kit rule: the index keeps ONE point per skill name, so a skill installed in two projects is scoped to whichever reindexed last). A same-project harness row takes the verdict of that harness's own personal scope (OMP reads `<cwd>/.codex/skills`, Claude does not), except the `<project>/.agents/skills` convention root — indexed under `zcode-project` but read by ZCode, OMP, Codex, DSH and Cline — which is foreign only under Claude. Claude's own `project:<cwd>` stays never-foreign. Known gaps (recorded, not fixed): skill dirs a session adds with `--add-dir`/`/cd` are invisible to the hook, so their project rows can be dropped as "other"; `project:<cwd>` is still never-foreign under harnesses that do not read `.claude/skills` at all (DSH, Cline, Codex). `=0` restores the pre-0.49.0 behavior (a project row passes unless its exact scope string is in `FOREIGN_SCOPES`, which it never is). [ADR-0059](docs/adr/0059-harness-complete-offer-isolation-echo-everywhere.md).
- `SKILL_ROW_ORIGIN` (`vendor/skill-search/skill_search/server.py`) — `search_skills`/`consult_candidates` rows drop the slash `command` field on every non-catalog row and gain `origin` (which harness's roots hold the indexed copy — `claude`, `codex`, `commandcode`, `omp`, `zcode`, `dsh`, `cline`, or `claude-synced`) and `disabled_in` (present when a plugin INSTALLED for Claude Code — `installed_plugins.json` — has every installed `<id>@<marketplace>` key switched off in the merged `enabledPlugins` layers, user → `<cwd>/.claude/settings.json` → `<cwd>/.claude/settings.local.json`: the per-turn hook's own invocability rule, so a stale key for an uninstalled marketplace never marks a plugin Claude can run; an unreadable registry gives no signal. Account-synced rows carry `disabled_in` naming every non-Claude harness), plus one response-level `note`. Read PER CALL — this is a query-time flag, not an index-shaping one, so it stays OUT of `scripts/engine_env.py`'s `ENGINE_ENV_KEYS` (the same reasoning `SKILL_BLOCKLIST`/`SKILL_CONSULT` stay out). [ADR-0058](docs/adr/0058-off-list-rule-exclusion-echo-row-provenance-synced-default-off.md).
- `ENFORCER_CHAIN_HINT` (`hooks/scripts/enforcer.py`) — appends a `CHAIN-HINT:` candidate line to every inject-bearing leg (mandate, mandate-only fallbacks, AUTHORIZED-SKIP lines) when this session used a skill declaring `next-skills:` within `ENFORCER_CHAIN_TTL_S` (900s). ## Guardrails

- The index holds **model-invocable `SKILL.md` skills only** — built-in slash-commands are excluded by design ([ADR-0001](docs/adr/0001-index-model-invocable-skills-only.md)). Don't "fix" their absence.
- The vendored `eval/` recall@k is calibrated to a *different* skill universe; a near-zero score is a wrong-universe artifact, not a weak retriever ([caveats §1](docs/caveats.md)).
- Hooks are **fail-silent and additive-only** — a telemetry failure must never block a turn. The two deliberate exceptions are the gates below: the openwiki commit parity guard and the blocklist `skill_guard.py` (a user-ordered disable is a gate, not telemetry — ADR-0046). Both block by design; both fail OPEN on internal error so a broken guard can never wedge the repo or skill invocation.
- **`git commit` is gated on openwiki parity.** `.claude/settings.json` wires a `PreToolUse(Bash)` hook to `scripts/openwiki_parity_guard.py`. Non-commit Bash calls pass through silently; a `git commit` (including compound `git add . && git commit` and `git -C <path> commit`) is **denied** if either deterministic check fails:
  1. **Version parity** — `openwiki/quickstart.md` is registered as a `driftcheck.json` mirror, so its `**Version:**` line must match `.claude-plugin/plugin.json` (the SSOT) alongside marketplace/CHANGELOG/README. There is no second version checker to drift.
  2. **Link integrity** — every relative link under `openwiki/` must resolve on disk. This catches the corrupted/half-finished-edit class that shipped a clobbered sentence and a dead link once already.

  It does **not** judge whether the wiki's prose is semantically current — nothing cheap can, and a guard pretending to would be theater; that is what `/openwiki:wiki update` is for. Verify locally with `python3 scripts/driftcheck.py driftcheck.json` (must exit 0). The guard **fails open** on any internal error — a broken guard must never wedge the repo — and `OPENWIKI_GUARD=0` is the emergency override. `.claude/settings.json` is un-ignored on purpose (`.gitignore`: `.claude/*` + `!.claude/settings.json`) so the wiring exists on every clone; the rest of `.claude/` stays ignored.
- **`git commit` also emits a graph-staleness NOTICE — a warning, never a block.** `.claude/settings.json` wires a second `PreToolUse(Bash)` hook to `scripts/graph_staleness_notice.py`. On a `git commit` it asks graphify's own `detect_incremental()` which **git-tracked** files are new or modified since `graphify-out/manifest.json`, and reports them as `additionalContext`. The commit proceeds.
  It **warns instead of denying, deliberately — do not "upgrade" it to a deny.** `openwiki/` is committed, so a stale wiki ships to every clone and the fix is a sub-second text edit: blocking is proportionate. `graphify-out/` is **gitignored** — it never ships, so a stale graph harms only the local session — and the fix is asymmetric: code staleness rebuilds via AST for free, but doc staleness costs LLM calls through the gateway. This repo is doc-heavy and writes plans/reports constantly, so a deny would tax every commit and buy nothing the post-commit rebuild doesn't already give.
  Scope is **git-tracked files only** — load-bearing: graphify indexes scratch dirs (`.remember/`, `.memsearch/`, `.gjc/`) that churn every turn, so an unscoped notice would fire on *every* commit forever, and a warning that always fires is one you train yourself to ignore. It never emits `permissionDecision` (an `"allow"` there would auto-approve every commit and silently disable the permission prompt). Code drift self-heals via graphify's **post-commit hook** (`graphify hook status`; installs post-commit + post-checkout, AST-only, no LLM); docs need `/graphify . --update`. **Fails open** — no graph on disk, no graphify installed, or any internal error → silent. Override: `GRAPH_NOTICE=0`.
  *Reconciles with the repo's fail-silent hook doctrine:* this one is telemetry, not a gate — it never blocks. The openwiki guard remains the sole deliberate exception that denies.
- **Ledger metrics are EPOCH-SCOPED — NEVER pool them across config changes.** This is the load-bearing
  trap: this repo changes the very things the ledger measures (gate floors, retrieval engine, doctrine,
  the embed shim) *almost daily*, so the invocation-ledger is a **sequence of short config epochs, not one
  dataset**. A rate pooled across them describes *no real configuration* and manufactures a false "measured"
  signal. The standing watch items per epoch (what to monitor, triggers, env-first actions) live in
  **[`docs/epoch-watch.md`](docs/epoch-watch.md)** — the single canonical reference; this rule governs HOW
  to measure, that doc governs WHAT to watch. Before citing ANY ledger rate (fallback / conversion / dodge / hit@k):
  1. **Find the current epoch start** — the last commit touching `hooks/scripts/enforcer.py` (thresholds/gates),
     `hooks/doctrine/skill-first.md`, `vendor/skill-search/skill_search/server.py` (retrieval), or
     `scripts/embed_server.py`: `git log --date=format:'%Y-%m-%d %H:%M' --pretty='%cd %h %s' -- <those paths>`.
  2. **Window to it:** `python3 scripts/analyze.py --since "<that datetime>"`. Never quote the all-time number.
  3. **Exclude contamination:** subagent / harness / `<task-notification>` traffic and your *own* meta/self-session
     turns are NOT representative (a heavy multi-agent session alone can swing the fallback rate 30+ points).
  4. **Respect sample size:** a fresh epoch may be too small to conclude — say **"insufficient data"** rather than
     pool backward to inflate n.
  5. **Design vs environment:** a metric shift that does NOT line up with a config commit (e.g. a per-day spike
     *between* releases) is **environmental** (shim/Docker/load), not a property of the code — do not attribute it
     to a design decision.
  This exact mistake — pooling ~15 epochs (v0.2→v0.12) and reading the aggregate as a current-state signal —
  already invalidated a full multi-agent analysis once (see the *Data-validity note* in
  `plans/reports/from-audit-and-openspace-syntheses-…-integrated-final-…-report.md`). Calibrate confidence to
  data-validity: an epoch-pooled or tiny-sample rate is **UNMEASURED**, never "measured".
