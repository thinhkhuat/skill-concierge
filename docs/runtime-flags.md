# Runtime flags — full reference

Moved verbatim from `AGENTS.md` → *Runtime flags* on 2026-10-08 (only relative links re-based for `docs/`). `AGENTS.md` keeps the one-line index table and the two invariants; this file keeps each flag's full text. Edit a flag's entry here when you change its code or default, and its table row in `AGENTS.md` in the same commit. `scripts/check_flag_docs_parity.py` (a `driftcheck.json` command check) fails when the two disagree: a flag in one but not the other, or a default that differs from the code's `os.environ.get` default.

Each is a one-var revert to the prior behavior (`ENFORCER_AUTHORIZED_SKIP`, `ENFORCER_CHAIN_HINT`, `ENFORCER_CROSS_HARNESS`, `ENFORCER_PROJECT_ISOLATION`, `ENFORCER_MINED_CHAINS`, `ENFORCER_MULTI_INTENT`, `ENFORCER_CHAIN_PROJECTION`, `ENFORCER_HARNESS_SKIP`, `ENFORCER_DETERMINISTIC`, `ENFORCER_JEV_ROUTER`, `SKILL_BLOCKLIST`, `SKILL_CONSULT`, `SKILL_CONSULT_ROUTE`, `SKILL_ROW_ORIGIN`, and `SKILL_BODY_TRIGGERS` default ON, `SKILL_FINDABILITY` default ON, as is `SKILL_JEVD_ENV_CHECK`, and so are `SKILL_CONSULT_JEV`, `SKILL_CONSULT_JEV_WIDEN` and `SKILL_TRIGGER_JEV_FILTER` (the last inert until a calibrated thresholds file exists); `SKILL_LLM_TRIGGERS`, `SKILL_SYNCED_ROOTS`, `SKILL_DECLARED_TRIGGERS`, `SKILL_SEARCH_COMPLEMENT`, `SKILL_CONSULT_SLOTS`, `SKILL_CONSULT_RRF` and `ENFORCER_JEV_HISTORY` default OFF; `SKILL_OWNER_AUTOSTART` default ON but not a "prior behavior" revert — the prior behavior was Docker, and `=0` only turns off the hook-side autostart nudges, not the owner architecture itself):

- `ENFORCER_MULTI_INTENT` (`hooks/scripts/enforcer.py`) — code default ON (ADR-0041), but **switched OFF on this machine's Claude Code via `~/.claude/settings.json` env as a trial**: the human-prompt backtest of the v0.46.0 epoch showed no lift (84 multi-intent offers → 5 with ≥2 takes vs control 7/98) at ~245 chars on about half of all offers. Other harnesses keep the default; `ENFORCER_CHAIN_PROJECTION` stays ON until epoch-watch v0.47.0 W6 decides. [ADR-0055](adr/0055-multi-intent-off-projection-pending.md).
- `ENFORCER_HARNESS_SKIP` (`hooks/scripts/enforcer.py`) — default ON; the harness-message lane: a prompt whose head is harness-generated (`<task-notification>`, `<system-reminder>`, cross-session/teammate messages and `[Cross-session idle notice]`s, "[Request interrupted…", "This session is being continued…", an OMP `omp-msum` summarizer wrapper) is authorized to skip before the refusal guard, consult route, embed and every Qdrant call — ledger band `harness_skip`, fourth `SKILL-CHECK:` leg, no chain hint. `=0` routes such prompts like any other. [ADR-0054](adr/0054-harness-message-lane-and-audit-fixes.md).
- `ENFORCER_DETERMINISTIC` (`hooks/scripts/enforcer.py`) — default ON since ADR-0054: `config/deterministic-routes.json` phrases pin the named skill when the prompt contains them as a whole word (a phrase never fires inside a longer word — `/cook` once pinned ak-cook from a `…/cookbooks` URL; `_route_matches`) to the top of the offer (score 1.0, retrieved twin dropped), computed BEFORE the embed step so a timeout cannot lose it. `=0` disables; an empty `routes` list is a no-op. Timeouts widened in the same ADR (`ENFORCER_EMBED_TIMEOUT` 0.5 s, `ENFORCER_QDRANT_TIMEOUT` 0.25 s — revert to 0.35 / 0.1 via the vars). Keep-off (ADR-0011) now lives in `~/.claude/skill-concierge/keep-off.json`, consent-only since ADR-0077 — never built or refreshed by `doctor --fix` or `setup.sh`; saved only by `scripts/build_keep_off.py --apply` after Thinh's yes, and hides nothing unless the map carries `"approved_by_user": true` ([ADR-0077](adr/0077-keep-off-map-is-consent-only.md)); `SKILL_CONCIERGE_KEEPOFF` overrides the path.
- `ENFORCER_JEV_ROUTER` (`hooks/scripts/enforcer.py`) — default ON; the Jev skill router (ADR-0061, superseding ADR-0060's yes/no leg, which replayed on real traffic skipped 48 % of turns where the agent really used a skill). English prompts only (`_is_english`: fewer than two non-ASCII letters — the calibration population's rule), at least one bench tier with its own key (`TYPESAFE_API_KEY` for `ts`, `CMD_API_KEY` for `cc`, `ENFORCER_JEV_KEY` or `FLYWHEEL_LLM_API_KEY` for `gw`, or a jevd that holds keys — `_jev_key`, checked in `_jev_route`), no named deterministic route. A worker thread started before the embed step builds the invocable catalogue (`_jev_catalog`: every installed `kind=base` point through `_row_invocable` — the same per-row test `_retrieve` applies — plus keep-off and blocklist), reads the conversation context from the payload's `transcript_path` (`_jev_context`: last assistant message tail + last 3 skills loaded), then makes two TypeSafe calls: a whole-catalogue Choice in ≤250-option chunks (top 5 per chunk → shortlist) and a rerank (Choice + one `fits` Noul per candidate, cookbook wording). `_jev_decide` (pure): best fit < `ENFORCER_JEV_FITS_FLOOR` (0.30) → authorized skip, band `jev_skip`, locked signature "Jev needs-a-skill gate" (audit `_AUTHORIZED_SIGNATURES` unchanged); else the rerank Choice's top 5 replace the embedding menu AND the getaway/actionability gates, headed "Whole-shelf ranking for this task" so the agent knows every skill it can use was judged (embedding offers keep "Preview … not the shelf"; ADR-0062). Joined after retrieval under `ENFORCER_JEV_BUDGET` (default and ceiling 7.8 s from start since ADR-0079, was 3.0 s; per call `ENFORCER_JEV_TIMEOUT` 1.5 s). Calls go through jevd when `JEVD_URL` names one (ADR-0080), else through the local index owner's warm `POST /jev` relay (and `/jev/cc` for Command Code, ADR-0081) (pooled HTTPS connections; fixed host/path; key forwarded, never stored; a timeout is never retried — ADR-0070; ported from the retired Docker embed shim); an owner without the route (404) or not listening → one direct call. Any failure, malformed answer or blown budget → the embedding path decides; embed/Qdrant down → a Jev verdict still serves. Every ledger row after an attempted route carries `jev` (`{ms, wide_ms, conf, fit, via, n, ctx, lead, model, floor, to}` — `model` is the pinned id Jev confirmed (a different returned id raises `JevModelMismatch` and the turn falls back), `floor`/`to` the env-tunable fits floor and per-call timeout, which leave no commit — or `{err, ms, leg: "router"}` — the `leg` tells a router error from the v0.50.0 leg's unmarked `{err, ms}`). Calibration: `scripts/extract_turn_labels.py` (private real-turn corpus under `~/.claude/skill-concierge/jev-calibration/`, never the repo) + `scripts/calibrate_jev_gate.py` (replay/curve/fit/rank/wide/policy, using the enforcer's own builders and `_jev_decide`; `live` reports epoch-watch W21-W24 on live traffic). Tests offline: `tests/test_jev_router.py`, `tests/test_jev_relay.py` (pool reuse, fresh-connection retry, no retry after a timeout); the chain-hint e2e sets `ENFORCER_JEV_GATE=0`. `=0` — or the ADR-0060 alias `ENFORCER_JEV_GATE=0` — restores the pre-v0.50.0 embedding-only path byte-identically. [ADR-0061](adr/0061-jev-skill-router.md).
- `ENFORCER_JEV_BENCH` (`hooks/scripts/enforcer.py`) — the ordered SystemOne tiers the router tries within one turn (ADR-0075). **When `JEVD_URL` names a running jevd** (`http` to loopback only, anything else ignored) and `GET {JEVD_URL}/ladder` answers within 0.3 s, jevd's ladder IS the bench (ADR-0080; its order, models, per-call `timeout_s` and `span_s` live in `~/.config/jevd/config.toml`, Command Code's 5.5 s span is `span_s = 5.5`): the hook still walks it, because a turn is two linked calls (ranking, then rerank on the SAME provider), pinning each call with `X-Jevd-Provider` and `X-Jevd-Budget`, sending no key, `via=jevd`, and the router event records the provider as `prov`. A jevd that holds no keys leaves the variable below in charge; every event the router emits records `bench` (`jevd` or `env`); when jevd answers but every provider fails, the hook does not retry them direct (the embedding path decides, a judgment call, ADR-0080). JEVD_URL unset, or jevd silent: the variable below applies unchanged, and the index owner's relay is its warm path for both TypeSafe (`POST /jev`) and Command Code (`POST /jev/cc`, ADR-0081: a fixed two-destination table, one path each, a pooled connection kept warm by a keyless GET, a request re-sent only when writing it failed; an owner that predates it answers 404 and the hook calls Command Code directly). The direct form: space-separated `<endpoint>:<model>`, `ts` = TypeSafe (`ENFORCER_JEV_URL`, `TYPESAFE_API_KEY`, the warm relay, `ENFORCER_JEV_TIMEOUT`), `gw` = the owner's gateway (`https://<FLYWHEEL_LLM_ENDPOINT host>/v1/systemone`, key `ENFORCER_JEV_KEY` else `FLYWHEEL_LLM_API_KEY`, `ENFORCER_JEV_GATEWAY_TIMEOUT` default 2.0 s), `cc` = Command Code (`ENFORCER_JEV_CC_URL`, default `https://api.commandcode.ai/provider/v1/systemone`; key `CMD_API_KEY`; always direct, never the relay; serves only the unpinned model `typesafe/jev`, so `rmodel` cannot show the Jev version there; every Jev request sends `User-Agent: skill-concierge` because its Cloudflare front refuses Python's default). `ENFORCER_JEV_CC_TIMEOUT` (default 5.5 s, refined from 5.0 s on the owner's order) is the `cc` tier's per-call timeout and its span: Command Code gets the whole 5.5 s, and TypeSafe is called only on an error or after 5.5 s with no answer (the owner's decision of 2026-10-06, interim, "at least for now"). Any failure, a timeout included, moves the turn to the next tier that still fits `ENFORCER_JEV_BUDGET` (7.8 s: 5.5 + TypeSafe's 1.5 + 0.8 for the catalogue read and thread start-up, since urllib's timeout bounds each socket operation, not the whole call; a rerank with under 0.5 s left in its tier, `JEV_RERANK_MIN_S`, is not sent and the turn falls through as a `TimeoutError`); a tier that cannot fit is recorded `NoTime` and skipped, and later tiers are still tried (ADR-0079; ADR-0075 ended the chain on a timeout). A Command Code answer arriving after 5.5 s is discarded and TypeSafe is billed too. A turn answered inside 5.5 s is one bill; the worst case is about 7.8 s of Jev time (about 8.9 s hook time against the 10 s kill) and two bills. Every valid measurement had a Command Code turn at 2.3-9.4 s against TypeSafe's 0.7-1.5 s. Turns past the span, valid rounds 2026-10-06: 2, 2, 3 and 6 of 12 (the last two Command Code only, at 5.0 s and 5.5 s spans), so a longer span did not lower the miss rate in that sample and some requests stall well past it; W38 on real traffic decides the rate; every router call is held to its limit by the clock (`_jev_call_capped`), because urllib's timeout bounds each socket operation, not the call; W38 on real traffic decides. With `ENFORCER_JEV_HISTORY=1` a history-caused skip that cannot be re-asked ends the turn without a Jev verdict (the embedding path decides) instead of falling through, which would bill a whole second turn. `ENFORCER_JEV_CC_TIMEOUT=3.3` restores the earlier cut-over design. The Command Code and DSH adapters kill the enforcer at 2.5 s and pass `ENFORCER_JEV_BUDGET=1.6`, so the `cc` tier is skipped there; Claude Code's hook timeout is 10 s (`hooks/hooks.json`). The router event records `model`, `tier`, `to`, `floor` and `fell`. Unset = `ts:<ENFORCER_JEV_MODEL>`, ADR-0061 behaviour; on this machine it is set in `~/.config/harness-env.sh`. [ADR-0075](adr/0075-jev-bench-tiered-systemone-endpoints.md), amended by [ADR-0079](adr/0079-command-code-jev-tier-and-timeout-fall-through.md).
- `SKILL_JEVD_ENV_CHECK` (`hooks/scripts/doctrine.py`) — default ON: at SessionStart, when `JEVD_URL` in the session's environment is unset or not what the enforcer accepts (an `http` URL on `127.0.0.1`, `localhost` or `::1`) but jevd answers `GET /health` with `status: ok` on `127.0.0.1` (port from jevd's `config.toml`, `JEVD_CONFIG` / `JEVD_HOME` honoured, default 4377; 0.3 s cap), the hook adds a `systemMessage` for the user and appends a `JEVD-ENV WARNING` line to the doctrine context, which every adapter forwards. Reason: the enforcer reads `JEVD_URL` from the environment the harness started with, so a session launched from a shell that predates `JEVD_URL` bypasses a running jevd and calls providers with that shell's keys, stale after a key rotation (found 2026-10-07). It fires again after a resume, clear or compaction, since the environment is unchanged. Silent when `JEVD_URL` is a loopback `http` URL, `ENFORCER_JEV_ROUTER=0` or `ENFORCER_JEV_GATE=0`, jevd is not running, or on any error; the doctrine is injected either way. `=0` turns the check off. Tests: `tests/test_doctrine_jevd_check.py`.
- `SKILL_CONSULT_JEV` (`scripts/consult_fit.py`) — default ON, evidence only (ADR-0076, owner's decision): `consult --fast` ranks candidates with a Jev fit matrix (one `choice` per sub-goal, a `fits` floor, an `avoid` check); the agent still composes the chain, and any failure falls back to inline analysis. `=0` exits before any I/O. Script-side, so not in `ENGINE_ENV_KEYS`. The first live `--eval` was `CHECK: INSUFFICIENT` (n=2); epoch-watch W34. [ADR-0076](adr/0076-jev-typed-questions-consult-triggers-history.md).
- `SKILL_CONSULT_JEV_WIDEN` (`scripts/consult_fit.py`, `widen`) — default ON: consult's step 2 pipes the user's request and the `consult_candidates` response (`top_n` 40) into `widen`, which puts Jev's whole-catalogue top 10 first, keeps the sieve rows after them, drops duplicates and cuts to 20 (each row tagged `source`: `jev`, `both`, `sieve`; a `jev` row has no `path`, so read it with `get_skill`). Any Jev failure returns the sieve rows and the card says `sieve: not widened`. `=0` returns the sieve rows with no Jev I/O. Script-side, so not in `ENGINE_ENV_KEYS`. Shipped on a pre-registered held-out gate: recall@20 24.1 -> 48.3, n=29, 7 gained and 0 lost, Holm p 0.0469 (narrow); the cases are a proxy, so the effect on real consult requests is unmeasured ([`gate raw`](../plans/261003-1907-consult-sieve-recall-fixes/reports/iter2-gate-raw.txt)); epoch-watch W37. [ADR-0078](adr/0078-consult-sieve-jev-widening.md).
- `SKILL_TRIGGER_JEV_FILTER` (`scripts/llm_triggers.py`, `scripts/trigger_filter.py`) — code default ON but **inert**: `active()` needs the flag AND a live thresholds file (`~/.claude/skill-concierge/trigger-jev-thresholds.json`), and none exists because the staging findability gate failed (name-neighbour bar, 11/3368 violations against 0 in the control). When active, a flywheel utterance is dropped if its own-vs-nearest-sibling Jev margin is under the threshold for the answering model; dropped phrases stay in `triggers.json` under `llm_triggers.jev`. Generator-side, so not in `ENGINE_ENV_KEYS`; set it in `~/.config/harness-env.sh`, not one harness's settings, so the detached `auto_flywheel` sees it. Every `triggers.json` writer holds the flywheel lock. ADR-0076.
- `ENFORCER_JEV_HISTORY` (`hooks/scripts/enforcer.py`) — default `0`: with `=1`, the router's rerank call (not the wide call) also sees redacted, text-only conversation history (typed user text and assistant text, tool names only, secrets redacted), sized by `ENFORCER_JEV_HISTORY_TOKENS` (10000) and `ENFORCER_JEV_HISTORY_BYTES` (2097152). Query-time, so not in `ENGINE_ENV_KEYS`. The `hist-compare` verdict was FAIL (follow-up recall +1.2 points against +3.0 required); turning it on is the owner's call and starts epoch-watch W36. ADR-0076.
- `SKILL_FINDABILITY` (`vendor/skill-search/skill_search/server.py`) — default ON: after a reindex that embeds or deletes points, `build_index` launches `python -m skill_search.findability --sweep` detached (from `~`, Claude view, throttled to one per 10 minutes), which writes `~/.claude/skill-concierge/findability.json` (`SKILL_FINDABILITY_PATH`) for doctor's read-only "Findability" row. `=0` stops the automatic sweep. Not index-shaping, so not in `ENGINE_ENV_KEYS`. [ADR-0074](adr/0074-findability-is-a-ratcheted-invariant.md).
- `SKILL_DECLARED_TRIGGERS` (`server.py`, `skills_discovery.py`) — **default OFF**: drops exclusion sentences ("Not for …") from trigger phrases and splits a guarded list-form `when_to_use` into declared phrases. Index-shaping, so it is in `ENGINE_ENV_KEYS`; `=1` plus a reindex turns it on. Off because it failed the precision bar on its own. [ADR-0074](adr/0074-findability-is-a-ratcheted-invariant.md).
- `SKILL_SEARCH_COMPLEMENT` (`server.py`) — **default OFF**, query-time: in `search_skills`, an installed row ranks ahead of an external-catalog row that scores within 0.08 of it. Off because it caused most precision violations. [ADR-0074](adr/0074-findability-is-a-ratcheted-invariant.md).
- `SKILL_CONSULT_SLOTS` (`vendor/skill-search/skill_search/server.py`, read per call by `_consult_slots_on`) — **default OFF**, query-time: `consult_candidates` reserves about 70% of the `top_n` rows (`CONSULT_INSTALLED_SHARE` 0.7) for installed skills and returns externals after them in a separate block, counted in the response's `blocks`; a tier that is short lends its unused slots to the other. Off because both pre-registered held-out gates failed: recall@20 33.7 -> 33.7 on n=83 ([iteration 1](../plans/261003-1907-consult-sieve-recall-fixes/reports/phase-03-gate-verdict.md)), and slots + RRF together at 40 rows recall@40 28.1 -> 33.3 on n=57, 5 gained and 2 lost, Holm p 0.2266 (D_SR40 FAIL, [iteration 2](../plans/261003-1907-consult-sieve-recall-fixes/reports/iter2-gate-raw.txt); [ADR-0078](adr/0078-consult-sieve-jev-widening.md)). Not index-shaping, so not in `ENGINE_ENV_KEYS`. Evaluation instrument: `scripts/sieve_recall.py`.
- `SKILL_CONSULT_RRF` (`server.py`, read per call by `_consult_rrf_on`) — **default OFF**, query-time: `consult_candidates` merges its per-query result lists by reciprocal-rank fusion (`CONSULT_RRF_K` 60) instead of the max raw score; `score` stays the best raw score, and `search_skills` and `_fuse_ranked` are unchanged. Off because the same gates failed: recall@20 33.7 -> 34.9 on n=83, short of the 5-point bar (iteration 1), and the iteration-2 D_SR40 FAIL above (it tested slots + RRF together). Not in `ENGINE_ENV_KEYS`. To try either flag, put it in that harness's MCP server env and restart the server — a running stdio server's env is fixed at spawn. The three `consult` SKILL.md query-wording changes failed the same gate and were not applied.
- `SKILL_OWNER_AUTOSTART` (`bin/skill-search-mcp`, `hooks/scripts/enforcer.py`) — default ON: `bin/skill-search-mcp` starts the local index owner when `/health` doesn't answer, and the enforcer hook starts it on a refused connection (never on a timeout or a 503, which mean busy or loading, not down). `=0` disables both hook-side autostarts; `setup.sh`'s own stop/restart after (re)install is unaffected.
