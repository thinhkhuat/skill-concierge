# Repository layout — full reference

Moved verbatim from `AGENTS.md` → *Repository layout* on 2026-10-08 (only relative links re-based for `docs/`). `AGENTS.md` keeps one line per area.

The full tree is in the README's *Architecture* section. The parts you will touch most:

- `skills/{skill-search,setup,doctor,skill-usage-audit,keep-on,blocklist,reputation,flywheel,catalogs,consult}/SKILL.md` — the plugin skills (router + maintenance + usage-audit + keep-on allowlist manager + blocklist disable-tier manager ADR-0046 + reputation badge manager ADR-0083 + flywheel utterance coverage/generation ADR-0027 + external catalog-roots manager ADR-0031 + consult deliberation layer ADR-0049)
- `scripts/` — `doctor.py` (health check), `analyze.py` (ledger; `--since`/`--until` window it by event time for before/after compares — don't split the ledger by hand), `apply-overrides.py` (keep-on writer; `--check`/`--if-changed` drift modes), `keep-on.py` (view/add/remove the always-on allowlist), `blocklist.py` (view/add/remove the disable list, ADR-0046), `reputation.py` (the owner's ❤️/⭐ skill ranking: list/add/remove/why, plus `suggest [--apply]` from usage, ADR-0083), `catalogs.py` (external catalog roots: list/add/remove/promote, ADR-0031), `llm_capsules.py` (capsule-dossier generator, ADR-0049), `consult_log.py` (consult verdict ledger rows, ADR-0049), `consult_fit.py` (Jev fit matrix for `consult --fast`, ADR-0076), `jev_client.py` (shared offline Jev client, ADR-0076), `trigger_filter.py` (Jev utterance filter: calibrate/backfill/reindex/report, ADR-0076), `embed_server.py` (retired warm embed shim — superseded by the local index owner, ADR-0070), `engine_env.py` (the single `ENGINE_ENV_KEYS` list every reindex path forwards from `.mcp.json`, ADR-0058 — see *Runtime flags*)
- `hooks/` — the in-generation governance layer: `enforcer.py` (per-turn SKILL-FIRST gate: embed→retrieve→floors/intent→ranked mandate, plus the AUTHORIZED-SKIP tier — five legs: getaway + intent (ADR-0015), self-referential (ADR-0019), harness-message (ADR-0054, pre-I/O), Jev skill router (ADR-0061, English prompts: Jev ranks the whole catalogue and re-checks a shortlist in a worker thread overlapping embed/Qdrant; supersedes ADR-0060's yes/no leg)), `skill_guard.py` (PreToolUse(Skill) deny on the blocklist — the disable tier's deterministic layer, ADR-0046), `skill_exclusions.py` (PostToolUse(Skill|get_skill) — echoes a just-loaded skill's own "not for" lines back deterministically, forcing an open re-rule instead of a silent switch; natively on Claude Code + ZCode, reached on OMP, Command Code, Cline and DSH through their adapters, which forward it the same load payload as `ledger.py`; quotes the copy the agent actually read via `tool_response` first, falling back to the index path then filesystem roots; ADR-0058, ADR-0059), `ledger.py` (invocation capture; a bare plugin-skill name is recorded as the menu's `plugin:name` with the typed form in `typed`, via the shared resolver `skill_names.py`, ADR-0083 0.61.2), `doctrine.py` (SessionStart standing-order injection), `auto_reindex.py` + `auto_overrides.py` + `auto_flywheel.py` (SessionStart self-heal: index + settings-override drift + utterance generation for new skills, ADR-0027 — fail-open, throttled, detached), `doctrine/skill-first.md` (the standing order — line-1 ruling `USING` / `SEARCH` / `NO SKILL: <why>`; know which offer you hold, whole-shelf ranking or preview; burden of proof on the skip; a lawful skip has exactly three sources — a shown search, a `SKILL-CHECK:` line, or a whole-shelf ranking whose top row the agent rules out by name (ADR-0082); real-or-ambiguous work escalates to a term-rich `search_skills` re-query, ADR-0056, ADR-0062; the off-list route + the re-rule duty, ADR-0058; continuing a skill already invoked this session, for the same task, skips the search but re-reads its body with `get_skill`, and a red-flags row sends "I'm still in <skill>" on new work to SEARCH, ADR-0063, ADR-0064, ADR-0065)
- `vendor/skill-search/` — vendored MCP engine (MIT · sowhan/skill-search) — **do not diverge silently**; the body-derived trigger points (`_extract_body_triggers`/`_trigger_phrases`, ADR-0016) are a direct engine-code patch, logged in [`VENDORED.md`](../vendor/skill-search/VENDORED.md) — re-apply it if the engine is ever re-vendored from upstream
- `.claude-plugin/{plugin,marketplace}.json` — plugin manifests
- `adapters/` — per-harness integration modules: `codex/` (`install.sh` syncs an *existing* Codex marketplace registration to this checkout's SSOT version via `codex plugin marketplace upgrade` + `add` — there is no `codex plugin upgrade` verb, and this installer never calls `remove`: a bare `add` refreshes an existing install in place, a failed `add` never uninstalls the previous copy (both verified live), and Codex has no CLI to disable a plugin or keep one disabled through a refresh, so an already-disabled plugin makes this script refuse right away, before `marketplace upgrade` or `add` runs — no mutating CLI call — rather than refreshing it first and only complaining afterward; refuses to downgrade a newer cache, both before AND after the CLI call; when the CLI refresh still lags — the marketplace only ever installs what's pushed — falls back to a `git archive HEAD` export into a NEW version-named cache dir, which this script's own fallback step never deletes (Codex's own `add`, by contrast, was verified live to wipe the plugin's ENTIRE cache dir — every version and staging dir — on every successful refresh; that is Codex's behavior, not this script's), with a loud unpushed-content notice; whether a live session loads hooks/MCP from that synced dir is unverified beyond `codex plugin list`; ADR-0033), `claude-code/` (`install.sh` keeps the reference harness's own plugin cache in sync via `claude plugin update skill-concierge@skill-concierge --json -y`, refusing a downgrade before AND after that call, falling back to a local `git archive` sync plus a backed-up, atomically-written `installed_plugins.json` repoint — never touching `enabledPlugins` or the shared venv — when the marketplace remote hasn't caught up to this checkout yet), `commandcode/` (mod adapter `skill-concierge.mod.ts` + install.sh + mcp.json, ADR-0038), `omp/` (extension module `skill-concierge.ext.ts` loaded via root `package.json` `omp.extensions`, install.sh — which also refreshes OMP's marketplace catalog clone whenever it lags the checkout's version, on every path including "Already current" — mcp.json, ADR-0039), `zcode/` (verifier/repair install.sh + manual-fallback mcp.json — ZCode needs NO adapter vehicle, it natively reads `.claude-plugin/` manifests, fires the plugin hooks, and auto-connects the plugin `.mcp.json`; ADR-0042), and `dsh/` (Cordis-plugin enforcement vehicle `skill-concierge.dsh.ts` riding `agent/pre-step`, installer writing the `skill-search` MCP row, the unlazy stop-hook and the enforcement plugin into each profile's `cordis.patch.yml` as `- insert:` patches (a bare `- id:` only overrides an existing entry — ADR-0059), reference mcp.json, ADR-0050 — DSH is a Cordis composition harness, not a Claude-format plugin consumer), and `cline/` (code plugin `skill-concierge.cline-plugin.ts`, loaded from the checkout through an installer-written `~/.cline/plugins/skill-concierge.ts`; `agent_plugin.py` + its manifest template `agent-plugin.json` generating the Agent Plugin in `~/.agents/plugins/skill-concierge/`; `mcp_row.py`, which only removes the old installer's `cline_mcp_settings.json` row; `install.sh`, which takes no options, writes the loader, generates the Agent Plugin and retires the old file-hook installer's marked shims; ADR-0086, which retired the ADR-0051 file-hook vehicle), and `opencode/` (a native OpenCode v2 plugin package `plugin/` — `{ id, setup(ctx) }` registering the skill-search MCP server via `ctx.mcp.transform` from the shared `.mcp.json`, doctrine + per-turn enforcer via `session.hook("prompt")`/`("context")` system parts, the blocklist deny via `permission.hook("evaluate")` delegating to `skill_guard.py`, ledger + exclusion echo via `tool.hook("execute.after")`, detached self-heal at setup — plus `install.sh` registering the plugin path in the global `opencode.json` `plugins` array and re-rooting the plugin's skills into `~/.config/opencode/skills/` behind a managed-names marker; ADR-0085). The OMP adapter never writes `~/.omp/agent/mcp.json` — OMP expands the plugin `.mcp.json`'s `${CLAUDE_PLUGIN_ROOT}` natively; the ZCode fallback likewise stays unwritten while the plugin layer is healthy.
- `package.json` — root manifest carrying the OMP extension hook: `{"omp": {"extensions": ["./adapters/omp/skill-concierge.ext.ts"]}}`.
- `.codex-plugin/plugin.json` + `.codex/hooks.json` — Codex adapter: manifest (no hooks field — auto-discovered) + repo-dev openwiki commit gate (ADR-0033)
- `config/keep-on.json` — the shipped SEED for the curated always-on allowlist (runtime copy seeded once into `~/.claude/skill-concierge/keep-on.json`, the canonical durable home; ADR-0025)
