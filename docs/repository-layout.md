# Repository layout — full reference

Moved verbatim from `AGENTS.md` → *Repository layout* on 2026-10-08 (only relative links re-based for `docs/`). `AGENTS.md` keeps one line per area.

This file is the canonical layout reference (the README carries no tree). The warm embed shim (`scripts/embed_server.py`, `bin/embed-shim`) and the Qdrant migration scripts are retired, archived in v0.64.1; the local index owner replaced them (ADR-0070). The parts you will touch most:

- `skills/{skill-search,setup,doctor,skill-usage-audit,keep-on,blocklist,reputation,flywheel,catalogs,consult}/SKILL.md` — the plugin skills (router + maintenance + usage-audit + keep-on allowlist manager + blocklist disable-tier manager ADR-0046 + reputation badge manager ADR-0083 + flywheel utterance coverage/generation ADR-0027 + external catalog-roots manager ADR-0031 + consult deliberation layer ADR-0049)
- `scripts/` — `doctor.py` (health check), `analyze.py` (ledger; `--since`/`--until` window it by event time for before/after compares — don't split the ledger by hand), `apply-overrides.py` (keep-on writer; `--check`/`--if-changed` drift modes), `keep-on.py` (view/add/remove the always-on allowlist), `blocklist.py` (view/add/remove the disable list, ADR-0046), `reputation.py` (the owner's ❤️/⭐ skill ranking: list/add/remove/why, plus `suggest [--apply]` from usage, ADR-0083), `catalogs.py` (external catalog roots: list/add/remove/promote, ADR-0031), `llm_capsules.py` (capsule-dossier generator, ADR-0049), `consult_log.py` (consult verdict ledger rows, ADR-0049), `consult_fit.py` (Jev fit matrix for `consult --fast`, ADR-0076), `jev_client.py` (shared offline Jev client, ADR-0076), `trigger_filter.py` (Jev utterance filter: calibrate/backfill/reindex/report, ADR-0076), `engine_env.py` (the single `ENGINE_ENV_KEYS` list every reindex path forwards from `.mcp.json`, ADR-0058 — see *Runtime flags*), `cmd_skill_bridge.py` (the Command Code colon-name bridge: `build` materializes a normalized copy of every skill Command Code's own name rule would SKIP — a colon in the frontmatter `name` (`ak:fix`), a name that does not match its own directory, an illegal character — into the shelf `~/.commandcode/skill-concierge-bridge` that the `skill-bridge` mod registers with `cmd.addSkillsPath()`; `verify` proves each copy legal, named like its directory, and every SOURCE unchanged by hash; `clean` removes only what its manifest names; `list` is read-only. Stdlib only, `--selftest`; tests: `tests/test_commandcode_bridge.py`), `cmd_agent_bridge.py` (the Command Code AGENT bridge: Command Code resolves a subagent's frontmatter `tools:` line against its own tool ids and drops every Claude Code name in silence, so a delegate written to write files and run builds launches with little more than `glob`+`grep`; `build` mirrors the Claude agent corpus into `~/.commandcode/agents` — the directory Command Code actually scans, since the ModApi has an `addSkillsPath` but no agent seam — translating each copy's `tools:`/`disallowedTools:` ids through one explicit table (`Read`→`read_file`, `Bash`→`shell_command`, `MultiEdit`→`edit_file`, …; `SendMessage` and `Task(<agent>)` dropped and NAMED, never invented), writing an omitted `tools:` key out as `"*"` (Command Code reads omission as NO tools, Claude Code as "inherit all"), resetting a non-Command-Code `model:` to `inherit`, renaming unambiguous camel-case body tool tokens, and adding ONE explicit adapter note where a body relies on delegation or peer messaging (Command Code subagents can neither spawn subagents nor message peers); sources are never edited (hashed into `_agent_bridge.json`; `verify` proves it), `clean` deletes only manifest-named files, and a file created inside Command Code itself is preserved and reported; `build` refuses a symlinked destination, because `~/.commandcode/agents` is normally a symlink to the shared `~/.claude/agents` corpus; `list` is read-only. Stdlib only, `--selftest`; tests: `tests/test_commandcode_agent_bridge.py`)
- `hooks/` — the in-generation governance layer: `enforcer.py` (per-turn SKILL-FIRST gate: embed→retrieve→floors/intent→ranked mandate, plus the AUTHORIZED-SKIP tier — five legs: getaway + intent (ADR-0015), self-referential (ADR-0019), harness-message (ADR-0054, pre-I/O), Jev skill router (ADR-0061, English prompts: Jev ranks the whole catalogue and re-checks a shortlist in a worker thread overlapping embed/Qdrant; supersedes ADR-0060's yes/no leg)), `skill_guard.py` (PreToolUse(Skill) deny on the blocklist — the disable tier's deterministic layer, ADR-0046), `skill_exclusions.py` (PostToolUse(Skill|get_skill) — echoes a just-loaded skill's own "not for" lines back deterministically, forcing an open re-rule instead of a silent switch; natively on Claude Code + ZCode, reached on OMP, Command Code, Cline and DSH through their adapters, which forward it the same load payload as `ledger.py`; quotes the copy the agent actually read via `tool_response` first, falling back to the index path then filesystem roots; ADR-0058, ADR-0059), `ledger.py` (invocation capture; a bare plugin-skill name is recorded as the menu's `plugin:name` with the typed form in `typed`, via the shared resolver `skill_names.py`, ADR-0083 0.61.2), `doctrine.py` (SessionStart standing-order injection), `auto_reindex.py` + `auto_overrides.py` + `auto_flywheel.py` (SessionStart self-heal: index + settings-override drift + utterance generation for new skills, ADR-0027 — fail-open, throttled, detached; their shared helpers live in `selfheal.py`), `auto_bridge.py` (SessionStart self-heal for the Command Code bridge shelf: regenerates the normalized colon-name copies before Command Code discovers skills — fail-open, throttled, INLINE rather than detached, deliberately, because the shelf is what Command Code reads at startup and a detached writer could rewrite a copy mid-discovery; `SKILL_BRIDGE=0` kills the run and `AUTO_BRIDGE_THROTTLE_S` sets the window; the work itself is `scripts/cmd_skill_bridge.py build`, whose fingerprint check makes a no-change run a no-op), `auto_agent_bridge.py` (SessionStart self-heal for the Command Code AGENT mirror: refreshes `~/.commandcode/agents` before the first delegate of a session can be spawned — fail-open, throttled, INLINE for the same reason as its sibling, and INERT while that path is still the symlink to `~/.claude/agents`, so an uninstalled machine fills no log; `AGENT_BRIDGE=0` kills the run, `AUTO_AGENT_BRIDGE_THROTTLE_S` sets the window, `AGENT_BRIDGE_DEST` moves the mirror; the work itself is `scripts/cmd_agent_bridge.py build`), `doctrine/skill-first.md` (the standing order — line-1 ruling `USING` / `SEARCH` / `NO SKILL: <why>`; know which offer you hold, whole-shelf ranking or preview; burden of proof on the skip; a lawful skip has exactly three sources — a shown search, a `SKILL-CHECK:` line, or a whole-shelf ranking whose top row the agent rules out by name (ADR-0082); real-or-ambiguous work escalates to a term-rich `search_skills` re-query, ADR-0056, ADR-0062; the off-list route + the re-rule duty, ADR-0058; continuing a skill already invoked this session, for the same task, skips the search but re-reads its body with `get_skill`, and a red-flags row sends "I'm still in <skill>" on new work to SEARCH, ADR-0063, ADR-0064, ADR-0065); `harness.py` (the one harness detector — the `.commandcode`, `.cline`, `.opencode` and other install-path markers — that `enforcer.py`, `doctrine.py` and `ledger.py` share); the bodies of the `--selftest` contracts for `enforcer.py` and `scripts/doctor.py` live in `tests/enforcer_selftest.py` and `tests/doctor_selftest.py` (the scripts load them into their own namespace; pytest runs them through `tests/test_enforcer_selftest.py` and `tests/test_doctor_selftest.py`)
- `vendor/skill-search/` — vendored MCP engine (MIT · sowhan/skill-search) — **do not diverge silently**; the body-derived trigger points (`_extract_body_triggers`/`_trigger_phrases`, ADR-0016) are a direct engine-code patch, logged in [`VENDORED.md`](../vendor/skill-search/VENDORED.md) — re-apply it if the engine is ever re-vendored from upstream
- `.claude-plugin/{plugin,marketplace}.json` — plugin manifests
- `adapters/` — per-harness integration modules: `codex/` (`install.sh` syncs an *existing* Codex marketplace registration to this checkout's SSOT version via `codex plugin marketplace upgrade` + `add` — there is no `codex plugin upgrade` verb, and this installer never calls `remove`: a bare `add` refreshes an existing install in place, a failed `add` never uninstalls the previous copy (both verified live), and Codex has no CLI to disable a plugin or keep one disabled through a refresh, so an already-disabled plugin makes this script refuse right away, before `marketplace upgrade` or `add` runs — no mutating CLI call — rather than refreshing it first and only complaining afterward; refuses to downgrade a newer cache, both before AND after the CLI call; when the CLI refresh still lags — the marketplace only ever installs what's pushed — falls back to a `git archive HEAD` export into a NEW version-named cache dir, which this script's own fallback step never deletes (Codex's own `add`, by contrast, was verified live to wipe the plugin's ENTIRE cache dir — every version and staging dir — on every successful refresh; that is Codex's behavior, not this script's), with a loud unpushed-content notice; whether a live session loads hooks/MCP from that synced dir is unverified beyond `codex plugin list`; ADR-0033), `claude-code/` (`install.sh` keeps the reference harness's own plugin cache in sync via `claude plugin update skill-concierge@skill-concierge --json -y`, refusing a downgrade before AND after that call, falling back to a local `git archive` sync plus a backed-up, atomically-written `installed_plugins.json` repoint — never touching `enabledPlugins` or the shared venv — when the marketplace remote hasn't caught up to this checkout yet; and `mod/`, the `concierge-enhancer` Claude Code mod (0.3.0), a second plugin in this repo's marketplace: it never rewrites the prompt; on a settled draft (the `pauseSeconds` pause, default 2 s, at least 4 words, not a slash command) or when the person presses the band's **Rank now** (also a chord from the prompt: Button `action` `app:cycleDiffBase`, default `ctrl+x b`, or the person's own keybinding), at most 2 runs per composed prompt, 1 of them automatic (`autoRank` option, default on), counted until the person sends it; inert when skill-concierge is disabled in the settings) `hooks/speculator.ts` spawns the installed `enforcer.py` in speculate mode (stdin `speculate`, real session id, transcript found by session id, Jev through jevd), which writes a ticket through `hooks/scripts/offer_ticket.py` and prints `skillConciergeSpeculation`, shown with `$.ui.status` and in a band above the prompt (`hooks/register.tsx`, the `AbovePrompt` hook: one rank row and at most one menu row, composing with other mods' bands via `next(e)`, yielding to a survey; digit insert keys `1`-`5` fill the skill's name at the cursor with `$.prompt.fill`, bound only over a draft because a bare digit in an empty box presses a band button); at Enter the hook serves the ticket's Jev verdict when the sent text, conversation context and ranking settings match, the ticket is under 5 minutes old and every served row still passes the blocklist, keep-off list and current Jev catalogue (`ENFORCER_TICKET`); a run still ranking is waited for until 3.5 s before the hook's Jev deadline, then the hook ranks live; the row keeping `q` as sent and adding `via`, `spec` and `jev.src`; `skill-concierge` must stay the first entry in `.claude-plugin/marketplace.json`, because `doctor.py` and the OMP installer read the first entry; tests `adapters/claude-code/mod/tests/` and `tests/test_offer_ticket.py`; the design is `plans/261012-1206-concierge-enhancer-redesign/design.md`), `commandcode/` (mod adapter `skill-concierge.mod.ts` + install.sh + mcp.json, ADR-0038), `omp/` (extension module `skill-concierge.ext.ts` loaded via root `package.json` `omp.extensions`, install.sh — which also refreshes OMP's marketplace catalog clone whenever it lags the checkout's version, on every path including "Already current" — mcp.json, ADR-0039), `zcode/` (verifier/repair install.sh + manual-fallback mcp.json — ZCode needs NO adapter vehicle, it natively reads `.claude-plugin/` manifests, fires the plugin hooks, and auto-connects the plugin `.mcp.json`; ADR-0042), and `dsh/` (Cordis-plugin enforcement vehicle `skill-concierge.dsh.ts` riding `agent/pre-step`, installer writing the `skill-search` MCP row, the unlazy stop-hook and the enforcement plugin into each profile's `cordis.patch.yml` as `- insert:` patches (a bare `- id:` only overrides an existing entry — ADR-0059), reference mcp.json, ADR-0050 — DSH is a Cordis composition harness, not a Claude-format plugin consumer), and `cline/` (code plugin `skill-concierge.cline-plugin.ts`, loaded from the checkout through an installer-written `~/.cline/plugins/skill-concierge.ts`; `agent_plugin.py` + its manifest template `agent-plugin.json` generating the Agent Plugin in `~/.agents/plugins/skill-concierge/`; `mcp_row.py`, which only removes the old installer's `cline_mcp_settings.json` row; `install.sh`, which takes no options, writes the loader, generates the Agent Plugin and retires the old file-hook installer's marked shims; ADR-0086, which retired the ADR-0051 file-hook vehicle), and `opencode/` (a native OpenCode v2 plugin package `plugin/` — `{ id, setup(ctx) }` registering the skill-search MCP server via `ctx.mcp.transform` from the shared `.mcp.json`, doctrine + per-turn enforcer via `session.hook("prompt")`/`("context")` system parts, the blocklist deny via `permission.hook("evaluate")` delegating to `skill_guard.py`, ledger + exclusion echo via `tool.hook("execute.after")`, detached self-heal at setup — plus `install.sh` keeping exactly one plugin entry in the global `opencode.json` `plugins` array and copying the plugin's skills into its own `~/.config/opencode/skill-concierge-skills/` behind a managed-names marker, registered once in `opencode.json` `skills` (`install.sh:72`); the server is registered with `codemode: false` (`plugin/index.ts:103`), a subagent child session gets no doctrine, menu or turn row, and a refused call is not logged; ADR-0085, amended by ADR-0089; tests `tests/test_opencode_plugin.py` (with `tests/opencode_plugin_harness.mjs`) and `tests/test_opencode_install_dedupe.py`). The OMP adapter never writes `~/.omp/agent/mcp.json` — OMP expands the plugin `.mcp.json`'s `${CLAUDE_PLUGIN_ROOT}` natively; the ZCode fallback likewise stays unwritten while the plugin layer is healthy. `adapters/lib/sync.sh` holds the installer helpers that were byte-identical (`_ver_ge`, `_is_own_checkout`, `_export_to`, `_refuse_unexportable_checkout`); the `claude-code`, `codex`, `omp`, `zcode` and `opencode` installers source it from their own path. `adapters/install-all.sh` is the release step after a push: it runs every `adapters/*/install.sh` (a glob, so a new adapter needs no edit there), continues past a failed one, exits non-zero if any failed, and ends with doctor's integration rows.
- `scripts/smoke.py` — the live release proof (ADR-0090): one headless turn per harness, each in its own temp folder with its own `SKILL_CONCIERGE_LOG`. `verdict()` holds the pass rule (an `offer` row whose band is `offer`, `jev_skip`, `getaway` or `intent_skip` with no outage fallback, and a `search` row); `SELF_HEAL_STAMPS` seeds throttle stamps in each run's log folder so no hook touches live state ([caveats §30](caveats.md)); CLIs and `opencode serve` run in their own process group; `CLI` lists how each harness is called; `_run_opencode` starts a private `opencode serve` on `SMOKE_OPENCODE_PORT` (default 4473) and drives it over HTTP. Stdlib only. Tests: `tests/test_smoke.py`.
- `adapters/install-all.sh` — runs every `adapters/*/install.sh` by glob, then doctor's integration rows, then `scripts/smoke.py` (its arguments pass through). Non-zero when any installer or smoke row failed. The release order is in `AGENTS.md` → *Setup & verification*.
- Cache-copy guard — `adapters/cline/install.sh`, `adapters/commandcode/install.sh`, `adapters/dsh/install.sh` and `adapters/omp/install.sh` (dev mode) exit 1 when run from `*/plugins/cache/*` (checked on the real path, after `--root` is parsed), because each writes its own checkout path into the harness config. OMP dev mode also keeps one `extensions` entry when the checkout moves. `adapters/opencode/install.sh` refuses already (ADR-0089). Test: `tests/test_installer_cache_guard.py`.
- Observable harness rows — Command Code: `adapters/commandcode/skill-concierge.mod.ts` governs only in `transformContext`, once per prompt, because print mode (`cmd -p`) never calls `transformInput`; `transformInput` logs manual slash rows and records the typed text ([caveats §29](caveats.md)). Test: `tests/test_commandcode_mod.py`. The installed copy in `~/.commandcode/mods/` carries its checkout path in an `INSTALLED_ROOT` line that `install.sh` writes through `adapters/commandcode/mod_root.py`, which doctor also reads; `adapters/commandcode/project_slug.py` names the project dir Command Code keeps for that checkout ([caveats §23](caveats.md) item 8). The colon-name bridge is the second Command Code mod (`adapters/commandcode/skill-bridge.mod.ts`, installed beside the first as `~/.commandcode/mods/skill-bridge.ts` and declared in `package.json` `commandcode.mods`): at factory time it registers the shelf `~/.commandcode/skill-concierge-bridge` through `cmd.addSkillsPath()`, which is the ONLY seam that puts a skill into Command Code's own catalogue — so `ak:fix`, `ck:copywriting` and friends, whose frontmatter `name` Command Code's rule rejects and SKIPS, load and auto-invoke under the names every other layer already uses (`ak-fix`). It has no hooks and no baked path: `SKILL_CONCIERGE_BRIDGE_SHELF` moves the shelf for both halves, and a missing shelf is one notice, never a broken session. Tests: `tests/test_commandcode_bridge.py`. The AGENT bridge is the third Command Code bridge and the one with no mod ([ADR-0094](../docs/adr/0094-commandcode-agent-tool-name-bridge.md)): Command Code resolves a subagent's `tools:` ids against its own names and drops every Claude Code one in silence, and reads an omitted `tools:` key as NO tools, so `scripts/cmd_agent_bridge.py` mirrors `~/.claude/agents` into `~/.commandcode/agents` with the frontmatter translated and a note where a body relies on delegation; the ModApi has no agent-path seam to register a shelf with (`cmd.addSkillsPath()` is skills-only), so `install.sh` replaces the `~/.commandcode/agents` symlink with a real, bridge-written directory — recording the target, never touching it, and re-linking if the build or the check fails — and `hooks/scripts/auto_agent_bridge.py` refreshes it at SessionStart. A file created inside Command Code itself is preserved and reported, never deleted. Tests: `tests/test_commandcode_agent_bridge.py`. DSH: `adapters/dsh/skill-concierge.dsh.ts` logs `search_skills` calls as `search` rows. OpenCode: `adapters/opencode/plugin/index.ts` sets `parent_lookup: "pending"` on a turn governed before the subagent check landed; `hooks/scripts/ledger.py` writes it, a landed lookup logs a `parent_lookup` row with `child` true or false, and `scripts/analyze.py` prints the `opencode M7` counts. OMP and DSH log no search row for a failed or blocked call. Test: `tests/test_ledger_harness_rows.py`.
- `tests/test_hook_definitions_pinned.py` — pins the whole `hooks` block of `hooks/hooks.json`. Codex skips a changed hook until the user trusts it again ([caveats §27](caveats.md)); changing one needs a `CHANGELOG.md` line saying so.
- `package.json` — root manifest carrying the OMP extension hook (`{"omp": {"extensions": ["./adapters/omp/skill-concierge.ext.ts"]}}`) and the Command Code package manifest (`{"commandcode": {"mods": ["./adapters/commandcode/skill-concierge.mod.ts", "./adapters/commandcode/skill-bridge.mod.ts"]}}`, plus the `cmd-mod` keyword), so `cmd mods add -g thinhkhuat/skill-concierge` loads the CC mod straight from the registry clone — and when that clone exists the installer PREFERS it, skipping the drop-in copies and removing a superseded one it wrote earlier, because both together register the same mods twice and doctor reports the double governance (ADR-0092).
- `.codex-plugin/plugin.json` + `.codex/hooks.json` — Codex adapter: manifest (no hooks field — auto-discovered) + repo-dev openwiki commit gate (ADR-0033)
- `config/keep-on.json` — the shipped SEED for the curated always-on allowlist (runtime copy seeded once into `~/.claude/skill-concierge/keep-on.json`, the canonical durable home; ADR-0025)
