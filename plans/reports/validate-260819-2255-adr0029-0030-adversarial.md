**Subject:** type: architecture (two Proposed ADRs + their source plan)

## Executive Summary

The ADRs' citations are unusually accurate (every spot-checked `file:line` resolves correctly, the marker-collision question resolves in their favor, and ADR-0030's parallel-embed claim has a real measured precedent in ADR-0008). But ADR-0029's core mechanism contradicts the code three ways: its motivating prompts are pre-gated to zero output before any hint could fire; the flat sidecar map reintroduces the exact last-writer-wins bug ADR-0028 documents as a live incident; and "bypasses nothing" is asserted with no mechanism, against the repo's own deterministic-route precedent that treats un-gated name resurfacing as an ADR-0011 bypass. ADR-0030's latency argument covers only the embed leg — per-clause retrieval plus per-clause actionability gating multiplies Qdrant traffic 3× with a 100ms cap per call, unmeasured by its own arming probe.

## Blocking Issues (FAIL)

1. **ADR-0029's motivating turns are unreachable by the mechanism as spec'd.** The Context names "go ahead" (2 words) and "now the docs" (3 words) as the failure case; `enforcer.py:537-538` returns 0 with *no injection of any kind* at `<= MAX_SHORT_WORDS (3)` before embedding. Longer vague continuations ("yes, continue with the docs now please") open with no imperative verb (`continue`/`go`/`proceed` absent from `_IMPERATIVE_VERBS`, `enforcer.py:97-103`) and land on the getaway or intent_skip legs — which inject authorized-skip lines, not the ranked mandate the ADR says the hint is "appended to". As written, the hint fires precisely *not* on the population it exists for. Fix: the ADR must specify hint placement per leg — (a) whether the chain-state check runs before the short-prompt pre-gate, (b) whether the hint rides authorized-skip and mandate-only fallback injects too — and pin each in the selftest. This is a placement decision with a real trade (hint-on-getaway = names surfaced with no retrieval behind them); it must be made in the ADR, not discovered in P1.

2. **The flat sidecar map reintroduces ADR-0028's documented multi-session incident.** `~/.claude/skill-concierge/next-skills.json` `{name: [successors]}` is written at reindex from `build_index`'s `desired` set, which is this session's CWD-scoped view (`skills_discovery.py:341-392`). ADR-0028:25-29 records exactly this failure for points ("last writer wins, forever, on a 30-minute hook throttle") and fixed it with per-point `scope`, `_prunable`, and a per-root `META_PATH` (`server.py:101-103, 526-532`); the manifest got per-project keying precisely because one shared file ping-ponged. ADR-0029's Relates-to list omits ADR-0028 entirely. Secondary arm of the same bug: hinted names can belong to scopes not visible in the reading session — the dead-recommendation problem `_scope_filter` exists to prevent (`server.py:671-673`). Fix: scope the sidecar like the points (write only own-scope entries, merge-don't-replace, prune only own scopes) or key it per project root like `META_PATH`; and filter hint names by session-visible scopes (or at least the personal+plugin scope) at read time.

3. **"Bypasses nothing" is asserted, not mechanized (ADR-0011 exposure).** The hint line names successors as free text; nothing in the Decision passes those names through keep-off, floors, or the catalogue. The repo already litigated this exact class: `_deterministic_hits` refuses to resurface a keep-off'd skill (`enforcer.py:262`, selftest 6b at `enforcer.py:740-752` — "a route pointing at a keep-off'd skill must NOT resurface it … (ADR-0011 bypass)"). A successor that has been keep-off'd (chronic never-take, exactly the population ADR-0011 suppresses) would be re-named in injected context every turn for 15 minutes. Fix: hint construction filters successors through `KEEPOFF` and through catalogue membership (the dangling-successor lint already warns at reindex; the enforcer should still drop names absent from the sidecar/index view), with a selftest case mirroring 6b. One-line ADR amendment + one selftest case.

4. **ADR-0030's budget argument stops at the embed leg; the Qdrant leg multiplies 3×.** "Passes the existing floors/gates independently" per clause means: 3 `_retrieve` calls + up to 6 `_intent_conversational` POSTs (2 per clause), each under its own 100ms hard cap (`enforcer.py:63-64`), issued serially over fresh urllib connections — worst case ~1100ms vs today's ~500ms, happy path roughly 2-4× today's ~100ms (`enforcer.py:62`). The stated arming gate ("latency probe showing ≤3 parallel embeds within the single-embed budget +50ms", ADR-0030 Decision) measures none of this and can pass while total enforcer latency regresses badly. Also unspecified: whether a conversational *clause* suppresses its group or the whole menu, and the intent gate is calibrated on whole prompts — bare clause fragments ("b" from "fix a, b, c in file") are out-of-distribution input to that classifier. Fix: (a) redefine the arming probe as end-to-end enforcer wall-clock vs the single-intent path; (b) state that Qdrant calls are parallelized (same `concurrent.futures` pool) or that the actionability gate runs ONCE on the full prompt (not per clause); (c) specify group-vs-menu suppression semantics.

## Advisory Suggestions (WARN)

5. **Concurrency/atomicity of both new JSON files is unspecified — and the repo already has the pattern.** chain-state.json is read-modify-written by concurrent PostToolUse processes (overlapping sessions): lost updates (one session's entry silently dropped → hint misses; tolerable) and, worse, non-atomic truncating writes from two writers can interleave into a *permanently* unparseable file — fail-open then means hints silently dead fleet-wide with zero surfaced error. The repo's own precedent for concurrently-read files is write-then-`os.replace` (`server.py:215-224` with rationale, `server.py:234-244`; `CHANGELOG.md:119-121`). Fix: tmp+rename for both files, and write-time pruning of TTL-expired sids (otherwise the file grows unboundedly and is re-read every prompt).

6. **Subagent bleed into chain-state and W3 metrics.** Hooks firing inside subagent calls carry `agent_id` (ADR-0020:20-21, quoting live docs); `ledger.py` never reads it, so a scoped worker's Skill invocation writes chain-state under the shared session sid — the *main* session's next prompt then hints that subagent skill's successors. Same root contaminates W3: ledger `auto` events are indistinguishable from main-session autos, so `--chains` bigrams mix lanes and the hint-follow rate counts them, against `AGENTS.md:93` ("Exclude contamination: subagent / harness … traffic"). Fix: positive-proof `agent_id` check when writing chain-state (mirror `doctrine.py:_is_subagent`, ADR-0020 Decision), and stamp autos (or offers) with a sub-flag / `hint:[names]` field so analyze can exclude — new keys only, which the plan already notes analyze tolerates.

7. **TTL semantics under-specified.** PostToolUse(Skill) fires at invocation/load, not completion; the 15-min TTL therefore (a) re-injects the hint on *every* prompt in the window (no consume-on-fire or refresh rule stated — repeated-push noise is the exact ADR-0009 concern 0029 itself flags), and (b) expires mid-work for any skill run longer than 15 min, missing the actual "after it completes" turn. State the intended repetition semantics in the ADR; consider consume-on-fire or re-arm on the successor's own invocation.

8. **`_mcp_env()` forwarding claim is confused and mis-attributed.** (a) `auto_reindex.py:48` builds from `dict(os.environ)`, so `ENFORCER_CHAIN_HINT` is already inherited by the detached reindex; the forward tuple (`auto_reindex.py:53-56`) exists to pull `.mcp.json` values — engine config that changes *index content* (the ADR-0026 gap, per `CHANGELOG.md:540, 221-225`). (b) The sidecar's content is flag-independent; gating the *write* on a *reader* flag buys nothing and creates stale-sidecar drift on an off→on toggle. (c) The v0.16.1 fix is ADR-0026's, not ADR-0027's. Fix: write the sidecar unconditionally at reindex; drop the forwarding sentence or justify it separately; correct the ADR reference.

9. **ADR-0030 residual spec gaps (all cheap to fix in text):** union-dedup "strongest clause" has no tiebreak (define: higher raw score, then earlier clause); no min-word/fragment rule for clauses (a bare "b" from comma-splitting embeds noise; VN sentence-final "rồi" yields empty tails — splitter must drop empties); digit-adjacent commas ("ports 4200, 4300, 6363") fragment single intents into junk groups (consider not splitting on commas adjacent to digits). The shim has no batch route (`embed_server.py:84-89`, single `text` per POST) — a `/embed` list variant reusing `server.embed_batch` (`server.py:345-351`) is simpler than 3 concurrent POSTs and worth naming as the preferred shape.

10. **Selftest coverage gaps vs repo norms.** 0029's evidence list omits: the keep-off-filtered-successor case (see #3), and an audit-parity pin that the CHAIN-HINT line and the new doctrine row never match `_is_authorized_skip_line` / `_AUTHORIZED_SIGNATURES` (`audit_skill_usage.py:89-91`) — the selfref lane set that precedent (`enforcer.py:781-789`). Cheap insurance against future wording drift.
